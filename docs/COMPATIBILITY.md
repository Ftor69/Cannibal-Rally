# Проверка платформы — 9 октября 2026

## Что проверено

Исходный репозиторий `/workspace/Cannibal-Rally` содержал только README с названием мешапа. В дереве проекта нет SDK, манифеста Melty, инструкций AGENTS.md, исходников мода или контракта загрузчика. Среди доступных инструментов нет Melty. В доступных пользовательских файлах не найдены документация Melty и The Forest. Команда Steam не обнаружена; игровых DLL и установленной игры для проверки не предоставлено.

Две попытки веб-поиска по Melty, SDK и The Forest вернули ошибку инструмента без результатов. Это **не доказывает отсутствие официальной документации или поддержки**. Нет проверенного первичного источника, позволяющего утверждать, что Melty поддерживает именно эту игру, версию, движок или способ импорта. Совместимость остаётся неизвестной.

## Решение

Использовать публичные зависимости Three.js 0.180.0, cannon-es 0.20.0, Vite 7.1.9, зафиксированные package-lock.json. API проверены сборкой и реальным запуском. Собственных вымышленных Melty API нет. `meltyCompatibility()` явно возвращает `available: false`; это диагностическая функция прототипа, а не API платформы.

Публичные справочные адреса зависимостей (не документация Melty):
- https://threejs.org/docs/
- https://github.com/pmndrs/cannon-es
- https://vite.dev/guide/

Нельзя считать веб-сборку подходящим форматом Melty без официальной спецификации. Не создан фиктивный манифест и не загружены игровые DLL. Не заявляется возможность переноса физики, острова или ресурсов непосредственно в The Forest.

## Что потребуется для адаптера

1. Официальная документация / SDK Melty и разрешённый пример проекта.
2. Подтверждение поддержки The Forest, точная версия игры и загрузчика.
3. Документированные точки доступа к вводу, игроку, сцене, физике, камере, AI и жизненному циклу модов.
4. Правила сборки / упаковки и локальный запуск без публикации.
5. Проверка конфликтов управления, камеры, урона и сохранений на пользовательском компьютере.

После получения контракта следует перенести независимые правила из core.js и заменить движок / мост согласно фактическим API. Сохранение JavaScript-кода возможно только если платформа его документированно допускает.

## Публикация и секреты

Проект не публиковался в Melty. Передача исходников через ветку и PR в GitHub разрешена пользователем; она не означает публикацию в Melty. Токены и закрытые инструкции не предоставлены и не включены. `.gitignore` исключает локальные настройки, ключи, токены и `melty-local/`; это дополнительная защита, а не замена проверке перед коммитом. Lockfile содержит только публичные зависимости. Публикация Melty требует отдельного разрешения пользователя.
